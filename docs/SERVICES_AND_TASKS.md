# 轻量入口与任务协作

版本 v0.1.4｜2026-10-31｜服务设计草案

本文件描述拟议服务及启动条件。当前仓库提供公开文档与反馈入口，尚未运营任务市场、商业授权代理、法律援助或诉讼资助服务。

## 1. 入口与独立站点

三千世界公共入口拟提供 IP 导航、规则索引、合作信息及共享资源记录。作品正文、图像和视频原则上保留在各 IP 自行管理的站点或所选服务中；入口展示摘要、链接及经许可的预览，不默认集中托管完整作品。

各 IP 原则上承担各自的内容托管、带宽和日常运营费用。公共入口自身的域名、托管、维护及第三方服务仍可能产生费用，应按实际方案记录，不承诺零成本。

站点独立不等于自动免除入口自身的责任。入口需维护链接和展示权限、反馈渠道及必要的更正处理。入口、推荐或共享池不应成为独立 IP 继续运营的唯一通道。

## 2. 商业使用与授权协作

拟帮助创作者说明商业使用需求、整理权利来源，并匹配相应权利人或合作方。需求应明确使用内容、用途、范围、期限、地域、署名与报酬等条件。

通用模板仅是协作工具，不能替代权利人同意，也不能保证所有项目采用相同定价或分配比例。网络维护者不因维护入口而自动取得代表各 IP 签署授权的权力。

实际达成的合作由相关方明确约定；具体权利边界继续适用[权利说明](../RIGHTS.md)。

## 3. 没有常设头衔，以任务组织合作

拟以有边界、可验收的任务组织创作与维护工作，而不是通过会员头衔自动授予常设管理职位。

任务仍须有发布方、执行方、验收人和付款责任人。任务制不消除实际管理责任，也不预先决定所有合作关系的性质。

一项任务至少说明：

| 项目 | 应明确的内容 |
|---|---|
| 工作范围 | 交付物、格式、期限及依赖资料 |
| 费用 | 报酬、付款方、支付节点、是否有服务费 |
| 验收 | 验收标准、修改次数、异议处理 |
| 权利 | 素材权限、交付物的使用许可或转让范围、署名与展示条件 |
| 变更与结束 | 增减需求、延期、取消及已完成工作的处理 |
| 信息 | 保密、个人信息和需要保留的工作记录 |

赏金、金额和服务费必须有真实出资方及明确规则，不默认从共享池支出。未确认预算的意向不得显示为已获资助的委托。

## 4. 资深贡献者优先邀约

拟在能力、可用时间和利益冲突核对的基础上，优先向符合条件的高级终身会员或资深贡献者发出适配任务的邀约。

“高级终身会员”的标准及其与跨三个 IP 会员资格的关系尚未确定；不能直接将两者视为同一身份。

优先邀约不等于免除能力判断、独占接单权、保证录用或固定收入。不会因会员身份自动取得作品管理权、资金审批权或商业授权权。支付支持、获得会员身份与获得有偿任务之间，不建立保证回报关系。

## 5. 法务支持与版权维权申请

拟探索三个层次的支持：

- 资料支持：整理可使用的合同清单、权利来源说明和证据准备指南。
- 专业转介：经当事人同意联系适合的专业服务方，明确费用与服务范围。
- 个案援助：共享池条件具备后，按公开程序评估咨询或维权费用支持申请。

申请应明确申请人、涉及权利、问题概述、所需帮助与预算。敏感证据和身份资料不应直接贴入公开仓库或榜单。

支持资格、预算上限、决定程序、利益冲突回避、进展记录和结束后的费用处理，须在服务启动前明确。申请不保证受理、资助、胜诉或赔付；当前没有常年法律顾问或诉讼资金承诺。

社区记录可以帮助整理贡献来源，但不单独完成侵权认定。内部表决不能代替专业判断或有权机关的处理。入口不以“执法机构”或统一仲裁者自居。

## 6. 约束包括发起人在内的维护者

治理设计不依赖任何人永远保持原先意愿。发起人同时是《申金》作者，作品利益、入口推荐与共享资源决策之间应清楚区分。

拟采用以下可核验的约束，实施细则仍需制定：

- 记录维护权限、决定依据、规则版本及适用时间。
- 推荐内容说明选择依据，并标明付费、关联或自有项目关系。
- 涉及自身任务或资源申请时披露关联，明确回避与复核方式。
- 资金启动前明确保管、审批、支付和核对的责任分工，不把账号控制等同于任意处分权。
- 重大规则变更说明影响范围，保留反馈、异议与纠错渠道。
- 明确退出及可导出记录，避免以控制入口阻断独立运营。

双人复核、多方批准等可作为待评估方式，不预设具体人数、链上钱包、陪审团或永久否决权。当前 GitHub 仍由发起人维护，并未完成独立治理或资金权限分离。

独立部署、代码复用或规则再发布须遵守各自许可；“分叉”不意味着能带走其他人的版权、身份数据或共享资金。当前仓库未授予统一开放许可。

## 7. AI 辅助与可持续成本

AI 可帮助个人搭建站点、整理资料、生成草稿和回答重复问题，降低部分重复劳动。但发布者仍需检查输出、权限、安全与维护；模型调用、存储、托管及人工复核可能产生费用。

不将 AI 自动判断用作最终权利裁定、法律意见、资助批准或付款指令。跨站记录先考虑当事人同意下的必要信息交换，不预设统一登录、公开贡献榜单或全量行为追踪。

## 8. 实施顺序

先维护导航、规则和明确的合作意向。出现有预算的需求后，再完成一项边界清楚的任务，核对交付、署名及实际付款。专业转介、个案援助和共享资金服务各自满足条件后再启动。

本方案不增加当前必须开发的系统，不改变以《申金》创作为主的工作重点。

## English summary

The public entry point is intended to link independently operated IP sites rather than host all creative works. Proposed services include scoped paid tasks, commercial-permission coordination and separately assessed rights-support requests.

Senior contributors may be considered for suitable invitations, without guaranteed work, income or authority. Responsibility, budgets, permissions, conflicts of interest and review procedures must be explicit. AI can assist operations but does not remove costs or human accountability. These services are not live.
